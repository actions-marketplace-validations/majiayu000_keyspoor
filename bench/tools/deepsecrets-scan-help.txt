usage: deepsecrets [-h] --target-dir TARGET_DIR
                   [--regex-rules [REGEX_RULES ...]]
                   [--regex-candidate-scoring-rules [REGEX_CANDIDATE_SCORING_RULES ...]]
                   [--hashed-values [HASHED_VALUES ...]]
                   [--semantic-analysis [SEMANTIC_ANALYSIS ...]]
                   [--variable-scoring-rules [VARIABLE_SCORING_RULES ...]]
                   [--excluded-paths [EXCLUDED_PATHS ...]] [--skip-bundles]
                   [--deep-max-size DEEP_MAX_SIZE]
                   [--confidence-level {all,low,medium,high,very-high}]
                   [--false-findings [FALSE_FINDINGS ...]] [-v]
                   [--reflect-findings-in-return-code]
                   [--process-count PROCESS_COUNT]
                   [--max-file-size MAX_FILE_SIZE]
                   [--multiprocessing-context {spawn,fork,forkserver}]
                   [--ci | --no-ci] --outfile OUTFILE
                   [--outformat {json,sarif,dojo-sarif}] [--disable-masking]
                   [--report-diagnostics]

DeepSecrets - a better tool for secrets search

options:
  -h, --help            show this help message and exit
  --target-dir TARGET_DIR
                        Path to the directory with code you'd like to analyze
  --regex-rules [REGEX_RULES ...]
                        Paths to your Regex Rulesets.
                        - Set 'disable' to turn off regex checks
                        - Ignore this argument to use the built-in ruleset.
                        - Using your own rulesets disables the default one. Add 'built-in' to the args list to merge rulesets
                        eq. --regex-rules built-in /root/my_regex_rules.json
  --regex-candidate-scoring-rules [REGEX_CANDIDATE_SCORING_RULES ...]
                        Controls rules for judging regex matches (candidates) before they are reported: placeholders,
                        language-like values, hosts, test paths. Used by regex rules that declare an "evidence" class.
                        - Ignore this argument to use the built-in ruleset
                        - Using your own rulesets disables the default one. Add 'built-in' to the args list to merge rulesets
                        eq. --regex-candidate-scoring-rules built-in /root/my_candidate_rules.json
                        - Give it no value to report regex matches unjudged, as before 2.2
  --hashed-values [HASHED_VALUES ...]
                        Path to your Hashed Values set.
                        Leave the flag out, or give it no value, to disable these checks
  --semantic-analysis [SEMANTIC_ANALYSIS ...]
                        Controls semantic checks (enabled by default)
                        - Set 'disable' to turn off semantic checks (not recommended)
                        eq. --semantic-analysis disable
                        Uses "--variable-scoring-rules" under the hood
  --variable-scoring-rules [VARIABLE_SCORING_RULES ...]
                        Controls rules for assessing variables as dangerous based on names, values, langs and filenames
                        - Ignore this argument to use the built-in (mature and robust) ruleset
                        - Using your own rulesets disables the default one. Add 'built-in' to the args list to merge rulesets
                        eq. --variable-scoring-rules built-in /root/my_var_scoring_rules.json
  --excluded-paths [EXCLUDED_PATHS ...]
                        Paths to your Excluded Paths file.
                        - Set 'disable' to scan everything (may affect performance)
                        - Ignore this argument to use the built-in ruleset.
                        - Using your own rulesets disables the default one. Add 'built-in' to the args list to enable it
                        eq. --excluded-paths built-in /root/my_excluded_paths.json
  --skip-bundles        Also skip minified JavaScript, source maps and bundles (*.min.js, *.map, *.bundle.js), whatever
                        --excluded-paths lists (except 'disable'). Most of them are larger than --deep-max-size and get the
                        fast analysis anyway.
  --deep-max-size DEEP_MAX_SIZE
                        Files larger than this many bytes get the fast analysis: the regex rules and the variable search,
                        without the language lexer, which costs most of the scan time on big files and rarely finds more there.
                        Default: 250000. 0 gives every file the full analysis.
  --confidence-level {all,low,medium,high,very-high}
                        The lowest confidence to report, from all to very-high (default: low).
                        "low" reports every finding; "medium", "high" and "very-high" keep confidence 3, 6 and 9 or more.
                        "all" also reports the regex matches the scanner judged not to be secrets (placeholders, examples),
                        at confidence 0 with an -INFO rule id.
  --false-findings [FALSE_FINDINGS ...]
                        Paths to your False Findings file.
                        Use to filter findings you sure are false positives
                        File syntax is the same as in regex rules
                        eq. --false-findings /root/my_false_findings.json
  -v, --verbose         Verbose mode
  --reflect-findings-in-return-code
                        Return code of 66 if any findings are detected during scan
  --process-count PROCESS_COUNT
                        Number of processes in a pool for file analysis (one process per file)
                        Default: number of processor cores of your machine or cpu limit of your container from cgroup.
                        If all checks are failed the fallback value is 4
  --max-file-size MAX_FILE_SIZE
                        Maximum size of a file (in bytes) the tool should analyze,
                        files with exceeding size will be ingored.
                        Big files (more than 5M) may contain useless blobs and cause performance degradation
                        Default: 0, which means "no limit".
  --multiprocessing-context {spawn,fork,forkserver}
                        How worker processes start. Default: forkserver where available (Linux, macOS), spawn elsewhere.
                        forkserver workers share the scanner already loaded in the server instead of loading it again.
  --ci, --no-ci         CI mode: no live progress bars, a plain progress line every 30 s, and no progress manager process.
                        Default: on inside a CI service (CI, GITHUB_ACTIONS, GITLAB_CI and similar variables) or when the
                        output is not a terminal; --no-ci forces the live display.
  --outfile OUTFILE
  --outformat {json,sarif,dojo-sarif}
                        "sarif": SARIF format (specification accurate, default)
                        "dojo-sarif": SARIF format (compatible with DefectDojo's parser)
                        "json": the old internal format, removed in 2.2.0 (exits with an error)
  --disable-masking     Secrets are rendered MASKED inside the report by default.
                        Use this flag if you want to render found secrets in plaintext but be extremely careful.
  --report-diagnostics  Add scan diagnostics to a SARIF report: every file found under the target directory in
                        run.artifacts (scan time in ms, status, skip reason, analysis depth) and per-file errors in
                        run.invocations.
